# PRD 010. 작업 방법의 검토와 확인 상태

Status: Planned

Depends on: [PRD 000](000-method-candidate-and-evidence.md) 완료. 뒤 번호 PRD에는 의존하지 않는다.

## Goal

사용자가 후보 방법을 근거와 함께 승인·거절하거나, 반복된 검증 근거를 확인해 사용할 수 있는 방법으로 **승격**한다. **다음 작업에서 방법을 실제 실행하지 않아도 승인/거절 상태와 적용 조건의 조회로 단독 완료한다.**

## Scope

1. PRD 000 후보의 절차·적용 조건·출처와 신뢰 구분·불확실성을 보여주고 사용자 검토 결과 또는 동일 유형의 다른 작업에서 나온 검증 결과를 당시 버전에 결속한다.
2. `candidate`/`confirmed`/`rejected`/`inactive` 의미를 구분한다. 단일 성공·모델 자기평가만으로 승격하지 않으며, 사용자 명시적 확인 또는 서로 다른 작업에서 반복된 검증 결과에 한해서만 확인 상태를 기록한다. 같은 요청·자료에서 나온 여러 실행(재시도, 재요청, 한 요청에서 만든 여러 후보)은 작업 하나의 근거로 세고, 그 반복 결과는 안정성·편차 근거로만 보존한다. 사용자 명시적 확인은 그 방법을 앞으로 기본으로 쓰겠다는 확인이며, 한 작업 결과를 받아들이거나 고른 사실로 대신하지 않는다.
3. 작업 유형·조건별 확인 방법과 원래 버전·판정 근거를 사용자 소유 로컬 조회 표면에 표시한다. 조건 불일치·상충 근거·철회된 확인은 기본 선택 후보로 제시하지 않는다.
4. 신뢰하지 않는 입력(024 quarantine 기준)에서 유래한 후보는 그 출처를 공유하지 않는 작업의 검증 또는 출처와 신뢰 구분을 함께 보여준 사용자 확인으로만 승격한다. 같은 출처를 다시 읽은 작업의 성공은 반복 검증으로 세지 않는다.

## Non Scope

- 확인 방법의 자동 실행, 이후 작업 결과의 품질 보장, 과거 실행의 재작성이나 rollback.
- 033 evaluator를 권한자로 만들거나 005 skill 설치만으로 방법이 확인됐다고 취급하는 것.
- 승격 근거를 만들려고 같은 요청·자료를 여러 방법으로 다시 실행해 대조하는 비교 실행.

## Parent Requirement Mapping

- [038 SPEC](../SPEC.md)의 소유 범위 2와 범위 4의 **적용 가능성 조회·선택 후보** 부분을 소유한다.
- 부모 수용 조건 2 중 승격·정확한 버전/조건 표시·부적합 차단을 소유한다. 실제 다음 작업에서 사용한 결과의 검증은 이 PRD의 종료 조건이 아니다.
- 같은 요청·자료의 반복 실행, 같은 신뢰하지 않는 출처의 반복, 한 작업 결과의 수락을 승격 근거에서 제외하는 규칙을 소유한다.

## Acceptance Criteria

1. 후보 하나를 거절하고 다른 후보를 사용자 명시적 확인 또는 같은 유형의 서로 다른 작업에서 나온 성공·검증으로 승격한다. 근거/버전/적용 조건, 근거별 출처의 신뢰 구분과 현재 확인 상태가 CLI·대화 조회에서 구별된다.
2. 단일 실행 성공, 같은 요청·자료의 반복 실행, 같은 신뢰하지 않는 출처를 공유하는 작업의 반복 성공, 한 작업 결과의 수락, 위조된 실행 ref, 미완료 결과, 상충하는 피드백 또는 조건에 맞지 않는 요청은 기본 후보 승격/선택을 만들지 않는다.
3. 재시작 뒤 같은 방법 버전과 사용자 확인 사실을 조회하며, 확인이 shell·Python·plugin·외부 발송 permission grant를 생성하지 않음을 검증한다.

## Closure Evidence

- 사용자 거절/확인과 추가 검증의 원본 ref·버전·조건이 연결된 전이 및 조회 결과.
- 단일 성공·같은 입력 반복·같은 신뢰하지 않는 출처 반복·결과 수락·오근거·상충 근거·잘못된 적용 조건의 승격 거절 테스트.

PRD 010은 **사용자가 검토할 수 있는 확인 방법 목록**으로 닫힌다. 뒤 번호의 자동 재사용·수정·롤백을 기다리지 않는다.
