# PRD 020. 확인 방법의 재사용·수정·철회

Status: Planned

Depends on: [PRD 000](000-method-candidate-and-evidence.md), [PRD 010](010-method-review-and-promotion.md) 완료. 뒤 번호 PRD에는 의존하지 않는다.

## Goal

확인된 방법을 다음 유사 요청에서 전제와 버전을 확인해 사용하고, 사용자가 수정·거절·비활성화·이전 버전 복원으로 다음 사용을 통제한다. 이 PRD의 실제 사용자 흐름이 [038 SPEC](../SPEC.md)의 종료를 완결한다.

## Scope

1. 요청마다 활성 방법의 적용 조건과 현재 버전, source 신뢰 경계를 검사한다. 적합하면 기존 005 skill 또는 024 recipe/일반 절차를 실행 입력으로 소비하고, 결과에 사용한 방법 ID·버전과 당시 검증 상태를 표시한다. 맞지 않으면 기존 일반 경로로 진행하며 이유를 보여준다.
2. 사용자가 문구·조건을 수정하거나 거절/비활성화하고 이전 확인 버전으로 복원할 수 있다. 변경 시 이전 버전과 사용자 소유 결정을 기록하고 동시 수정·stale 버전 CAS를 거부한다.
3. 작업 뒤 실패 피드백은 새 후보 또는 수정 근거가 될 수 있어도 기존 확인 방법을 자동 덮어쓰지 않는다. 이미 시작된 작업의 방법 버전과 산출물을 소급 변경하지 않는다.
4. 실행 시점의 030/004 tool·hook·confirmation·credential·sandbox 경계를 다시 통과한다. 방법 확인은 실행 허가가 아니다.
5. 방법은 일하는 방식만 바꾸고 사용자가 명시한 결과물 형식(필드·순서·구성·파일 형식)을 덮어쓰지 않는다. 형식 지정이 없는 요청에서만 방법의 기본 형식을 제안할 수 있고, 명시된 형식과 방법의 형식이 충돌하면 사용자 지정을 따른다.

## Non Scope

- 033의 local artifact apply/rollback이나 부작용 전체 복구, 024 workflow engine 재구현.
- 036의 선제 모니터링, 037의 신규 전문 하네스, 원격 방법 배포/marketplace.

## Parent Requirement Mapping

- [038 SPEC](../SPEC.md)의 소유 범위 3과 4의 실제 사용·수정·되돌리기 부분을 소유한다.
- 부모 수용 조건 2의 후속 작업 사용 부분(사용자가 명시한 결과물 형식 유지 포함), 조건 3–5의 수명주기·충돌 방지·실제 사용자 표면을 소유한다.

## Acceptance Criteria

1. 사용자 소유 격리 자료에서 후보→확인된 방법을 만들고 유사 요청 한 건을 실제 처리한다. 결과에서 정확한 방법 버전·전제·source를 확인하며 전제가 다른 요청에는 해당 방법을 적용하지 않는다. 결과물 형식을 명시한 유사 요청에서는 방법이 다른 형식을 담고 있어도 사용자가 지정한 형식이 유지된다.
2. 방법을 수정·거절/비활성화하고 이전 확인 버전으로 복원한 뒤 재시작한다. 이후 같은 요청은 최신 사용자 선택만 따르고 거절한 절차를 기본 사용하지 않는다.
3. 두 수정의 경합, stale 버전, 조작된 근거, 실패 실행을 성공 근거로 승격하려는 입력은 확인 방법을 덮지 못한다. 변경 이전 실행의 기록은 당시 버전을 유지한다.
4. CLI 또는 대화 표면에서 제안 조회→확인→다음 작업 사용→철회를 한 흐름으로 관찰한다. 명령 실행/발송이 필요한 방법도 기존 gate를 통과하지 않으면 사용되지 않는다.

## Closure Evidence

- 사용 전제·방법 버전과 실제 user turn 결과의 연결, 사용자 수정/비활성/복원 전후 표면 기록.
- 동시 수정·stale/오근거·거절 뒤 무음 재활성 방지와 기존 004/030 실행 gate 회귀 테스트.
- 명시된 결과물 형식과 방법의 형식이 충돌하는 요청에서 사용자 지정 형식이 유지된 결과.
- 이전 방법 버전 복원과 이미 일어난 tool side effect는 다른 의미임을 보여주는 사용자-visible 상태.

PRD 020은 앞선 후보·확인 결과만 소비해 **다음 작업에서의 재사용과 사용자 철회**로 닫힌다. 뒤 번호의 기능이나 모든 외부 부작용 rollback을 요구하지 않는다.
