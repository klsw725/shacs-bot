# 038. 근거 있는 작업 방법 학습과 재사용 아키텍처 명세

Status: Planned

Consumes: 005 skill discovery, 018 evaluation helpers, 024 workflow recipes, 030 trusted resources, 033 recorded trajectory and improvement evidence

## 목적과 완료 경계

이 스펙은 사용자에 대한 사실을 기억하는 것과 **문제를 해결할 때 유용했던 방법을 배우는 것**을 분리한다. 한 작업의 성공·실패·사용자 피드백에서 재사용할 절차를 제안하고, 근거와 적용 조건을 검토한 뒤 이후 유사 작업에 사용하거나 원래 방법으로 되돌리는 사용자 경험을 소유한다. 단순 skill 파일 저장, 033의 로컬 artifact CAS/rollback, 024의 workflow recipe 실행을 방법 학습 완료로 재명명하지 않는다.

이 스펙은 036의 지속 감시와 037의 전문 방식 선택을 기다리지 않는다. 기존 단일 session의 일반 도구 실행이나 기존 [024 recipe](../024-dynamic-workflows-and-harness-orchestration/SPEC.md) 결과, 사용자가 직접 제공한 절차를 입력으로 삼아 **후보 → 검토 → 확인/거절 → 적용 → 수정/되돌리기**를 독립적으로 검증할 수 있어야 한다.

## 소유 범위

1. **방법 후보와 근거:** 사용자 선호·개인 사실·현재 작업 조건과 재사용 가능한 절차를 다른 종류로 다룬다. 후보에는 목적, 적용 가능한 작업과 전제, 제안된 단계, 출처가 되는 실제 결과 또는 사용자 피드백, 확인하지 못한 부분과 버전을 남긴다. 외부 텍스트나 실행 결과의 일회성 문장을 검증된 절차로 바로 쓰지 않는다.
2. **확신과 승격:** 관찰된 후보, 확인된 방법, 거절/비활성 상태를 구분한다. 같은 유형의 작업에서 반복된 검증 결과 또는 사용자의 명시적 확인이 있을 때만 기본 후보로 승격한다. 승격 사실은 결과 자체의 올바름, 다음 작업의 성공, tool 권한 부여를 의미하지 않는다. 근거가 상충하거나 적용 조건이 달라지면 기본 사용을 멈추고 사용자가 판단할 수 있게 한다.
3. **사용자 소유 수명주기:** 사용자는 제안·근거·적용 조건·버전과 현재 활성 방법을 읽고, 문구/조건을 수정하거나 거절·비활성화·이전 버전으로 되돌릴 수 있다. 적용 중에 변경된 방법은 이미 실행된 결과를 소급해 바꾸지 않는다. 수정·승격·되돌리기는 현재 사용자 소유 로컬 자료에 기록되고 동시 수정 충돌을 조용히 덮지 않는다.
4. **사용 시점:** 유사 요청이 들어오면 활성 방법이 적용 가능한지 먼저 확인하고, 적합하면 사용자에게 어떤 방법을 참고했는지 결과와 함께 보여준다. 맞지 않으면 일반 경로로 진행하고 실패 이유 또는 대체 방법을 설명한다. 참고된 절차는 실행 당시의 버전과 근거에 결속하며 실패 피드백은 새 후보나 정정 근거가 될 수 있어도 조용히 기존 방법을 덮지 않는다.

| [024](../024-dynamic-workflows-and-harness-orchestration/SPEC.md) | 현재 recipe/plan과 검증 결과를 방법의 입력·실행 수단으로 소비 | 새 workflow engine, verifier, child/merge 정책, recipe 실행 계약 재소유 금지 |

방법을 저장할 물리 형식이 skill/recipe와 겹쳐도 **검토 상태·적용 조건·근거·버전의 의미 owner는 038**이다. 저장 매체나 특정 모델을 완료 조건으로 고정하지 않으며, 한 번 제안했다고 자동 활성화되는 원격 marketplace나 인격별 독립 하네스를 만들지 않는다.

## 반드시 지킬 것

- 한 번 성공한 결과나 모델의 자기평가만으로 기본 절차를 조용히 바꾸지 않는다. 실패·누락된 근거는 성공으로 합성하지 않고 이전에 확인된 버전은 보존한다.
- 사용자 피드백과 관측된 실행 사실을 구분한다. 방법의 근거가 참조하는 실행 기록과 적용 조건은 수정되지 않은 원래 사실로 추적할 수 있어야 한다.
- 저장한 방법의 문구가 Python·shell·plugin 실행, 외부 발송, secret 접근, sandbox 적용 여부를 승인하지 않는다. 실제 실행은 그 시점의 030/004 경계를 다시 통과한다.
- 다른 사용자/워크스페이스의 방법을 자동 공유하거나 remote marketplace로 배포하지 않는다. 036의 선제 감시, 037의 새 전문 하네스 구현은 이 스펙의 완료 조건이 아니다.

## 수용 조건

1. 사용자 소유 workspace의 실제 또는 기록된 한 작업에서 방법 후보와 근거를 만든다. 단일 성공만 있는 후보는 다음 작업의 기본 방식으로 자동 활성화되지 않으며, 사용자 선호 항목과 별도로 조회된다.
2. 같은 유형의 추가 검증 또는 사용자 확인이 있으면 확인된 방법으로 승격되고, 유사 요청에서 정확한 버전·적용 조건을 함께 사용한다. 전제가 맞지 않거나 근거가 부족한 요청은 해당 방법을 쓰지 않으며 이유를 표시한다.
3. 사용자가 잘못된 방법을 수정·거절·비활성화하거나 이전 확인 버전으로 되돌린다. 재시작 뒤에도 해당 상태가 유지되고, 다음 작업에서 더 이상 거절된 방법이 기본값으로 사용되지 않는다.
4. 동시 변경·오래된 버전으로의 수정, 틀린 출처, 실패 실행을 성공 근거로 둔 승격 시도는 기존 확인 방법을 덮어쓰지 않고 명시적으로 실패한다.
5. CLI 또는 실제 대화 표면에서 제안 조회·사용자 확인·다음 작업의 재사용·철회를 한 흐름으로 관측한다. 저장된 텍스트의 존재나 artifact rollback 테스트만으로 이 스펙을 완료 처리하지 않는다.

위 검증은 036이나 037이 없어도 기존 skill/recipe와 한 번의 작업 결과를 사용해 수행할 수 있다. 완료는 배운 방법의 수명주기에 한정되며 임의의 전문 분야 결과가 늘 옳다는 보장이 아니다.

## 실행 PRD와 독립 종료

각 PRD의 사용자-visible 결과는 뒤 PRD 없이 확인할 수 있다. 앞 번호의 완료된 자료만 소비하고 036/037의 구현은 요구하지 않는다. 구현 전 상태는 모두 `Planned`다.

| PRD | 유일하게 소유하는 결과 | 앞선 PRD 소비 | 자체 완료 표면 |
|---|---|---|---|
| [000 후보·근거](prds/000-method-candidate-and-evidence.md) | 실행/피드백 근거, 적용 조건, 비활성 후보 조회 | 없음 | 후보 조회·재시작 뒤 동일 근거 |
| [010 검토·승격](prds/010-method-review-and-promotion.md) | 사용자 확인 또는 반복 검증으로 확인/거절 상태와 적합성 조회 | 000 | 확인 방법 목록과 부적합 차단 |
| [020 재사용·수정·철회](prds/020-method-reuse-edit-and-revert.md) | 다음 작업의 버전 결속 사용, 수정·비활성·이전 버전 복원 | 000, 010 | 제안→확인→사용→철회의 실제 표면 |

소유 범위 1·수용 조건 1은 000, 범위 2와 조건 2의 승격/적합성 판단은 010, 범위 3–4의 실제 재사용·수정과 조건 2의 사용 및 조건 3–5는 020이 소유한다. 020의 전체 사용자 흐름은 앞선 각 PRD의 독립 종료를 소급 변경하지 않는다.
