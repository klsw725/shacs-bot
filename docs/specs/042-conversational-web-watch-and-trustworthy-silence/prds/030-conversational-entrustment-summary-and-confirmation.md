# PRD 030. 대화형 위임 요약과 확인

Status: Planned

Depends on: [PRD 000](000-web-page-observation-and-condition-decision.md), [PRD 010](010-change-failure-recovery-and-gap-notification.md), [PRD 020](020-decision-deadline-reminder.md) 완료. 뒤 번호 PRD에는 의존하지 않는다.

## Goal

사용자가 대화로 맡기면 어시스턴트가 **무엇을, 어디서, 어떤 조건으로 살피고 어떻게 알릴지** 요약해 보여주고, 사용자가 확인한 것만 위임·관측·알림 설정·마감으로 한 번에 설정한다. 이 PRD가 [042 SPEC](../SPEC.md) 전체의 실제 사용자 흐름을 닫는다.

## Scope

1. **요약 만들기:** 대화 요청이나 어시스턴트의 제안에서 URL, 볼 값(PRD 000 등록 후보의 지금 값과 위치), 구체 조건, 확인 주기, 알림 대상, 실패 알림 기준 시간, 선택적인 결정 마감과 알림 시점을 담은 요약을 만든다. 막연한 바람은 지원 조건 종류로 바꿔 제안한다. 지원하지 않는 조건·URL·알림 대상, 볼 값을 찾을 수 없는 페이지는 이유와 대안을 요약에 표시한다. 페이지 내용은 PRD 000의 등록 후보 단계로만 읽으며 요약의 URL·조건·주기·알림 대상을 바꾸지 못한다.
2. **확인 결속:** 요약은 고유 ID와 revision을 가지며 원래 session·channel·chat·발신자에 결속된다. 확인은 같은 발신자의 것만 인정하며 두 가지뿐이다. (1) 그 요약이 어시스턴트의 가장 최근 응답이고 대화에 대기 중인 요약이 그것 하나일 때 보낸 정해진 확인 응답("응", "네", "맞아", "그렇게 해" 등 사용자 문서에 적은 목록). (2) 현재 요약 ID와 revision을 담은 지원 채널의 버튼. 가장 최근·유일 조건은 (1)에만 적용한다. 다른 요약 표시나 재시작으로 닫힌 요약과 이전 ID·revision은 어느 방식으로도 인정하지 않는다. 그 밖의 응답은 위임을 만들지 않고 다시 묻는다. 무응답, 다른 요약 표시, 재시작은 대기 중인 요약을 닫는다.
3. **일괄 설정:** 새 위임이 확인되면 PRD 000의 첫 기준 절차로 값을 다시 읽는다. 보여준 값과 다르면 바뀐 요약을 새 revision으로 다시 보여주고 확인을 받는다. 같으면 036 위임(동의 근거: 요약 확인), PRD 000 관측과 첫 기준, PRD 010 알림 설정, PRD 020 마감을 한 번에 설정한다. 일부만 설정된 상태를 남기지 않는다.
4. **대화로 조회·수정:** "마지막으로 언제 확인했어?" 같은 질문에 PRD 000·010의 상태 사실로 답한다. 조건·URL·알림 대상·마감 변경은 새 요약 확인을 거친다. 확인된 변경이 URL·추출 기준·조건·주기를 바꾸면 첫 기준 절차를 다시 거치고, 알림 대상·기준 시간·마감만 바꾸면 해당 revision만 올리고 비교 기준을 유지한다. pause/resume/done/clear는 036 명령이나 확인을 거친 대화 요청으로 처리하며, 그 뒤 기준 처리는 036과 PRD 000을 따른다.

## Non Scope

- 사용자 자료를 훑어 요청하지 않은 일을 제안하는 기능, 여러 페이지 위임.
- 036 `/work` 명령과 `propose_entrusted_work` 제안의 의미 변경. 그 제안에서 일반 `yes`를 동의로 보지 않는 규칙은 그대로다.
- 예약·구매·발송 승인. 036의 별도 결정 경계를 유지한다.

## Parent Requirement Mapping

- [042 SPEC](../SPEC.md)의 소유 범위 1·8과 수용 조건 1·7을 소유한다.

## Required Contract

1. 확인 전에는 위임·관측·알림 설정·마감·wake가 없다. 일회성 질문 뒤에는 활성 위임이 없다.
2. 확인 판정을 모델의 추측에 맡기지 않는다. 판정이 불분명하면 만들지 않는다.
3. 위임 확인은 tool permission grant나 예약·구매·발송 승인이 아니다.
4. 요약에 표시한 값(URL·볼 값·조건·주기·알림 대상·기준 시간·마감)과 저장된 값이 같다.

## Acceptance Criteria

1. 실제 대화 진입점(agent REPL 또는 지원 channel), `127.0.0.1/32`만 허용한 시험용 profile의 로컬 HTTP 서버, 로컬 SMTP, 시험용 시계로 요청 → 요약 → 확인 → A/A/무관/B → 변화 알림 한 건, 확인 실패 → 실패·회복 알림, 마감 알림을 끝까지 실행한다.
2. 일회성 질문, 애매한 응답, 다른 발신자의 확인(버튼 포함), 바뀐 요약에 대한 이전 확인, 가장 최근 응답이 아닌 요약에 대한 확인 응답, 새 요약 표시로 닫힌 요약이나 이전 ID·revision을 담은 버튼, 재시작 뒤의 확인에서 위임이 생기지 않는다. 요약과 확인 사이에 값이 바뀌면 다시 확인을 요구한다.
3. 지원하지 않는 조건이나 알림 대상, 볼 값을 찾을 수 없는 페이지는 요약 단계에서 이유와 함께 안내되고 위임이 생기지 않는다. 페이지에 넣은 지시 문구가 요약 내용을 바꾸지 않는다.
4. 대화에서 마지막 성공 확인 시각과 현재 상태를 물으면 저장된 사실과 같은 답을 받는다. 조건 변경은 새 요약 확인 뒤에만 적용되고, 알림 대상이나 마감만 바꾸면 비교 기준이 유지된다.

## Closure Evidence

1. 실제 대화 transcript, 저장 상태, 수신 메일을 연결한 end-to-end 기록.
2. 확인 결속·애매한 응답·다른 발신자·재시작·일괄 설정 원자성·페이지 지시 문구 테스트.
3. 사용자 문서에 대화형 위임 사용법, 확인 응답 목록, 비보장 범위를 기록.

PRD 030은 앞 PRD에서 닫힌 관측·알림·마감 결과만 소비한다. 자체 요약·확인 조건과 실제 end-to-end 흐름을 충족하면 뒤 PRD 없이 종료한다.
