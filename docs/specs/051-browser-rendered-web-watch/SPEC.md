# 051. 브라우저로 읽는 웹 감시 구현 명세

Status: Planned

Consumes: 010 network guard, 029 durable wake·lease, 036 위임·관측·판정 fact, 042 웹페이지 source·추출 기준·조건·실패 구간·알림·대화형 요약, 049 container 브라우저·SOCKS5 proxy·process gate, 050 로그인 유지 프로필과 조작 상태

## 목적과 완료 경계

[042](../042-conversational-web-watch-and-trustworthy-silence/SPEC.md)의 웹 감시는 페이지를 내려받아 정적 HTML에서 값을 읽는다(`normalized_static_text_v1`). 자바스크립트가 그려야 값이 나오는 페이지는 `static_content_unavailable`로 남고, cookie를 보내지 않으므로 로그인해야 보이는 페이지도 감시하지 못한다.

이 스펙은 042 감시에 **브라우저로 읽기**를 더한다. 감시 확인이 [049](../049-container-browser-computer-use/SPEC.md)의 container 브라우저로 페이지를 열고, 그려진 글에서 042와 같은 방식으로 값을 읽는다. 사용자가 [050](../050-browser-takeover-and-saved-login/SPEC.md)의 로그인 유지를 켰다면 로그인한 상태로 볼 수도 있다.

브라우저로 읽기는 **페이지를 열어 읽기만** 한다(사용자 결정 2026-11-08). 누르기·입력·스크롤 같은 조작은 하지 않는다. 그래서 049의 `browser_act` 판정을 쓰지 않고, 비대화형으로 도는 감시가 승인 질문을 만들 일이 없다. 버튼을 눌러야 나오는 값은 이 스펙의 범위가 아니다.

완료되면 사용자는 다음을 경험한다.

- 정적 읽기로 값을 찾지 못한 페이지에서, 요약이 "브라우저로 읽기"를 제안하고 그렇게 읽은 값을 보여 준다. 사용자가 확인하면 그 방식으로 감시한다.
- 로그인 유지가 켜져 있으면 요약에서 "로그인한 상태로 보기"를 고를 수 있다. 로그인이 풀려 값을 못 읽으면 042의 확인 실패 알림이 그 까닭의 하나로 로그인 만료를 알린다.
- 브라우저를 대화가 쓰고 있는 동안 예정된 확인은 실행되지 않고 실패로 기록된다. 그 상태가 042 기준 시간을 넘으면 확인 실패 알림이 간다.
- 그 밖의 042 동작(조건, 판정, 변화·실패·회복·공백·마감 알림의 때와 중복 막기, 대화로 조회·수정)은 그대로다. 알림에 붙는 확인 한계 글만 읽기 방식에 맞게 바뀐다.

이 스펙은 049·050의 닫힌 결과만 소비한다.

## 소유 범위

1. **읽기 방식:** 042 `web_page` source의 관측 계획에 읽기 방식 `fetch`(042 그대로, 기본)와 `browser`, 그리고 `browser` 방식의 로그인 여부를 둔다. 둘은 관측 revision(URL·추출 기준·조건·주기)에 들어가고, 저장된 계획, 미리보기 token, 계획 digest에 포함된다. 방식이나 로그인 여부를 바꾸면 새 요약 확인을 거치고 042처럼 첫 기준을 다시 잡는다. 로그인한 화면과 안 한 화면은 같은 주소·고정 문구라도 다른 값일 수 있기 때문이다.
2. **그려진 글 추출 기준 `rendered_text_v1`:**
   - 브라우저로 URL을 열고 주 문서의 load와 그 뒤 network가 조용해질 때까지(상한 있음) 기다린 뒤, 문서의 보이는 글(`document.body.innerText`)을 DevTools로 읽는다.
   - 그 글에 042 `normalized_static_text_v1`의 정규화(Unicode NFC, 연속 공백 줄이기)를 적용하고, 042와 같은 앞뒤 고정 문구·occurrence·숫자 해석·문구 조건 규칙으로 값을 읽는다. 추출 기준 버전은 `rendered_text_v1`로 남긴다.
   - 주 문서의 HTTP 상태와 최종 URL은 DevTools의 응답 기록으로 042와 같이 남기고, 글을 읽은 그 주 문서(loader)에 묶는다. 042의 `rate_limited`·`http_error`·`Retry-After` backoff는 주 문서의 응답에 적용한다.
   - 049 소유 범위 3의 마지막 보장을 그대로 쓴다. 글을 읽기 직전과 직후에 주 문서의 주소와 loader를 확인해, `http:`·`https:`가 아니거나 그 사이에 문서가 바뀌었으면 그 결과를 버리고 실패로 남긴다.
   - 읽기에는 042처럼 한도가 있다. 전체 시간 한도, 읽는 글의 크기 한도와 잘림 기록, 다 그려지지 않았을 때의 실패 분류를 PRD 000이 정한다. 대기 한도에 닿았다는 것만으로 그때의 글에서 값을 읽어 성공으로 남기지 않는다.
   - 정확한 대기 조건과 상한은 PRD 000이 정한다.
3. **감시용 브라우저 실행:**
   - 감시 확인은 provider·agent turn·`browser` tool 없이 watcher가 049 브라우저 runtime을 직접 쓴다. 띄울 때는 049 process gate와 SOCKS5 proxy를 지난다.
   - proxy의 주소 확인은 042 규칙을 따른다. `tools.ssrfWhitelist`와 관계없이 공개 주소만 열고, 로컬 주소는 production 빌드에서 쓸 수 없는 종료 시험용 profile에서만 연다. 대화용 브라우저(049, 사용자의 `tools.ssrfWhitelist`를 따른다)와 감시용 브라우저는 띄울 때 정한 이 설정을 공유하지 않는다.
   - 감시용 브라우저의 시작은 provider 요청이나 대화형 승인 없이 049 process gate를 지나야 한다. 지금 판정이 시작을 허용하지 않으면 gate를 우회하거나 classifier를 부르지 않고, 권한을 까닭으로 한 `browser_unavailable`로 기록한다. PRD 000은 실제 gate와 가짜 process 실행기로 허용된 시작과 거절된 시작을 확인한다.
   - 확인 한 번마다 브라우저를 띄우고, 읽고, 닫는다. 로그인하지 않는 감시는 049처럼 새 임시 프로필을 쓰고 닫을 때 지운다. 로그인한 상태로 보는 감시는 050 `browser/profile/`을 쓴다.
   - 페이지는 자바스크립트를 실행하지만 감시는 누르기·입력·스크롤을 보내지 않는다. 내려받기와 올리기는 049처럼 막고, `http:`·`https:` 밖의 내용은 소유 범위 2의 확인으로 버린다.
   - 049 소유 범위 2는 페이지가 새 탭을 열면 그 탭으로 옮기지만, 감시는 새로 열린 탭을 닫고 따라가지 않는다. 값은 처음 연 탭의 주 문서에서만 읽는다.
4. **브라우저 공유:**
   - 049의 브라우저는 한 process에 하나다. 감시 확인 때 브라우저가 이미 떠 있으면(대화가 쓰는 중이거나 050 넘겨받기 중) 확인을 실행하지 않고 실패 `browser_busy`로 기록한다. 다음 확인은 042 주기대로 예약한다.
   - 감시 확인이 브라우저를 쓰는 동안 대화의 `browser` 호출과 `/browser takeover`는 049·050의 "다른 쪽이 쓰는 중" 결과를 받는다.
   - 화면 보기가 열려 있으면 감시 확인의 페이지도 보인다. 보기만 할 수 있고 넘겨받을 수 없다.
5. **실패 분류:** 042 실패 분류에 아래를 더한다. 042 실패 구간·기준 시간·회복 알림의 의미는 그대로다.
   - `browser_unavailable`: 브라우저를 띄울 수 없음(공식 container 밖, `tools.browser.enable` 꺼짐, Chromium 없음이나 시작 실패, process gate가 시작을 허용하지 않음, 로그인 감시인데 `persistLogin` 꺼짐이나 프로필 잠김).
   - `browser_busy`: 소유 범위 4.
   - `rendered_content_unavailable`: 그려진 글에서 앞뒤 고정 문구를 찾지 못함(`static_content_unavailable`의 브라우저판).
   - 로그인 감시의 `rendered_content_unavailable` 실패 알림은 "로그인이 풀렸을 수 있다, `/browser takeover`로 다시 로그인하라"는 글을 붙인다. 로그인 만료를 따로 알아내지는 않는다.
   - 알림마다 붙는 확인 한계 글(지금은 "정적 페이지 글만, JavaScript·로그인·cookie 없음")은 저장된 읽기 방식과 로그인 여부에 맞게 적는다. 알림의 때와 중복 막기는 그대로다.
6. **대화형 등록:**
   - 042 요약의 미리보기가 `static_content_unavailable`이면, 브라우저를 쓸 수 있는 설정에서 같은 URL을 브라우저로 한 번 읽어 후보를 다시 만들고 요약에 "브라우저로 읽기"와 그 값을 보인다. 사용자가 처음부터 브라우저로 읽어 달라고 하면 바로 브라우저로 읽는다.
   - `persistLogin`이 켜져 있으면 요약에서 "로그인한 상태로 보기"를 고를 수 있다. 요약은 로그인한 계정의 내용을 읽는다는 것, 읽은 값이 042처럼 저장되고 확인한 알림 대상으로 보내진다는 것, 페이지 글 전체·화면·cookie·로그인 정보는 관측 fact·알림·상태 조회·diagnostics에 남기거나 보내지 않지만 로그인 기록 폴더(050 `browser/profile/`)에는 cookie가 남고 페이지 내용을 담은 방문 기록·사이트 자료가 남을 수 있으며 그 폴더 전체가 050의 비밀 파일로 다뤄진다는 것, 로그인이 풀리면 확인 실패가 된다는 것을 적는다. 사용자가 확인한 로그인 여부가 계획에 저장된다(소유 범위 1).
   - 확인 순간 다시 읽기(042)는 같은 방식으로 한다. 브라우저를 다른 쪽이 쓰고 있으면 기다리지 않고 다시 확인을 요청한다.
   - 042의 등록 후보 규칙(결정적 파서, 페이지 글이 요약을 바꾸지 못함)은 그대로다.
7. **표면과 문서:** 042 상태 조회(CLI/API, 대화)에 읽기 방식과 로그인 여부를 보인다. `docs/USAGE.md`의 웹 감시 설명에 브라우저로 읽기, 로그인 감시, 새 실패 분류와 한계를 적고 README를 맞춘다.

## 반드시 지킬 것

- 감시 확인은 페이지를 열어 읽기만 한다. 누르기·입력·스크롤·키를 보내지 않는다.
- 감시 확인은 provider·agent turn·`browser` tool을 쓰지 않는다.
- 감시용 브라우저는 `tools.ssrfWhitelist`와 관계없이 공개 주소만 연다(시험용 profile 빼고).
- 브라우저가 이미 떠 있으면 감시는 그 브라우저를 쓰거나 닫지 않는다.
- 로그인하지 않는 감시는 050 프로필을 쓰지 않는다. 로그인 감시는 사용자가 요약에서 고른 것만이다.
- 042의 저장 범위를 지킨다. 그려진 글 전체, 화면 캡처, cookie를 관측 fact와 알림·조회·진단 출력에 남기지 않는다. 감시는 화면을 캡처하지 않는다. 확인한 추출 값과 근거는 042처럼 남고 알림으로 간다. 050 프로필에 브라우저가 남기는 자료는 이 규칙의 예외다(앞선 스펙에서 바꾸는 것).
- 글을 읽기 직전과 직후의 주 문서가 같은 `http:`·`https:` 문서가 아니면 그 결과로 값을 남기지 않는다.
- 값을 찾지 못하면 추측하지 않는다(042 그대로). 브라우저로 읽기는 `fetch`로 찾지 못한 값을 다른 위치에서 대신 고르지 않는다.
- `Cargo.lock`에 새 crate를 더하지 않는다. 필요해지면 멈추고 사용자에게 묻는다.
- Cargo 테스트는 가짜 DevTools 서버, 가짜 process 실행기, 시험용 시계로 돈다.

## 수용 조건

1. 읽기(Cargo, 가짜 DevTools 서버): `browser` 방식의 관측이 그려진 글에서 042의 A → 무관 변화 → B 흐름을 `suppress`·`suppress`·`notify_candidate`로 남기고, 추출 기준이 `rendered_text_v1`이다. 주 문서 429는 `rate_limited`와 backoff가 된다. 고정 문구가 없으면 `rendered_content_unavailable`이고 성공을 합성하지 않는다. 읽는 사이 주 문서가 바뀌거나 `http:`·`https:`가 아닌 문서가 되면 값이 남지 않는다. 대기 한도에 닿은 읽기는 화면에 옛 글과 고정 문구가 있어도 성공이 아니고, 크기 한도를 넘은 글은 잘림으로 기록된다. 알림의 한계 글이 읽기 방식과 로그인 여부에 맞다.
2. 실행(Cargo): 감시 확인이 provider 요청과 `browser` tool 호출 없이 끝나고, 누르기·입력·스크롤 DevTools 명령이 없다. 로그인하지 않는 감시는 임시 프로필, 로그인 감시는 `browser/profile/`로 뜬다. 페이지가 연 새 탭은 닫히고 그 탭에서 값을 읽지 않는다. 감시용 proxy가 `tools.ssrfWhitelist`에 넣은 사설 주소를 거절한다. 실제 process gate가 시작을 허용하지 않는 설정에서는 브라우저 process가 시작되지 않고, provider 요청 없이 권한 까닭의 `browser_unavailable`이 남는다.
3. 공유(Cargo): 대화가 브라우저를 쓰는 동안의 확인은 `browser_busy`로 기록되고 다음 확인이 예약된다. 시험용 시계로 기준 시간을 넘기면 실패 알림이 한 번 가고, 브라우저가 비어 다음 확인이 성공하면 회복 알림이 간다. 감시 확인 중의 `browser` 호출과 `/browser takeover`는 "다른 쪽이 쓰는 중"을 받는다.
4. 등록(실제 `AgentLoop` turn, 가짜 provider): 정적 내용에 값이 없는 페이지에서 요약이 브라우저로 읽은 값을 보이고, 확인하면 `browser` 방식의 감시가 생긴다. `persistLogin`이 꺼져 있으면 로그인 선택지가 없다. 로그인 여부가 계획·미리보기 token·계획 digest에 들어가고, 기존 감시의 로그인 여부를 바꾸면 새 요약 확인 뒤 첫 기준을 다시 잡는다. 로그인 감시의 요약에 값이 저장·발송된다는 안내와, 감시 기록·알림에는 페이지 글·cookie가 남지 않지만 로그인 기록 폴더에는 남는다는 구분이 있다. 로그인 감시의 `rendered_content_unavailable` 실패 알림에 다시 로그인하라는 글이 있다.
5. 실제 Docker(opt-in 스크립트, 사용자 승인 뒤). 사용자의 data directory는 쓰지 않는다. 049 수용 조건 6의 별도 test page container가 자바스크립트로 값을 그리는 페이지와 cookie가 있어야 값이 보이는 페이지를 낸다. 시험용 profile에서 두 페이지의 감시가 값을 읽고, 값을 바꾸면 변화 알림이 로컬 SMTP로 한 번 간다.
6. fmt, workspace clippy `-D warnings`, 변경한 package 테스트가 통과한다. 전체 workspace 테스트는 사용자 승인을 받아 실행한다.

위 조건은 051의 단독 종료 기준이다. 수용 조건 5는 사용자가 돌리지 않기로 결정할 수 있다. 그러면 그 PRD의 종료 확인에 결정과 이유, 확인하지 못한 것을 적고 scoped로 닫는다.

## 남은 위험과 한계

- 버튼을 누르거나 입력해야 나오는 값, 스크롤해야 불러오는 값은 감시하지 못한다.
- 그려진 글은 페이지가 언제 다 그려졌는지에 따라 달라질 수 있다. "다 그려짐"은 PRD 000이 정하는 규칙으로만 판단하므로, 그 규칙을 만족하면서도 아직 옛 값이 보이는 페이지에서는 옛 값을 읽을 수 있다. 같은 화면을 두 번 읽어 같은 값이 나온다는 보장은 없다.
- 대화용 브라우저가 떠 있는 동안 감시는 `browser_busy`로 밀린다. 050의 답 기다리는 시간(기본 30분)과 넘겨받기 동안도 같다. 브라우저가 닫히면 정해진 주기대로 다시 확인한다.
- 페이지는 자바스크립트를 실행하므로 `fetch`보다 많은 요청을 보낸다. 사이트가 자동화된 브라우저를 막으면 `http_error`나 `rendered_content_unavailable`이 된다. 이를 우회하지 않는다.
- 로그인 감시는 사용자 계정으로 페이지를 연다. 사이트가 접속 기록을 남기고, 로그인 기록은 050의 위험(같은 container, sandbox 꺼짐)을 그대로 가진다.
- 로그인 만료를 따로 알아내지 않는다. 로그인 화면이 같은 고정 문구를 담고 있으면 다른 값을 읽을 수 있다. 042의 앞뒤 고정 문구 규칙이 이를 줄인다.
- 감시 확인마다 브라우저를 띄우므로 `fetch`보다 느리고 메모리를 많이 쓴다.
- 화면 보기를 열어 둔 사람은 감시가 연 페이지(로그인 감시면 계정 내용)를 볼 수 있다.
- 로그인 감시의 값(계정만 볼 수 있는 값)은 042처럼 관측 fact에 남고 알림 대상 Email로 간다.
- 050 프로필에는 로그인 감시가 연 페이지의 방문 기록과 사이트 저장 자료가 남는다.
